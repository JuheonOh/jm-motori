# AI slop 정리 기록

분석 기준: `main@9e235eb`, PR 기준: `origin/main@9ced9c0`, 2026-10-10. 별도 `codex/ai-slop-cleanup` 작업 공간에서 진행합니다.
기존 `codex/design-v2` 작업과 보존용 `/versions/`·`archive/legacy-html/` 파일은 유지합니다.

## 범위와 정리 순서

1. 현재 화면의 회귀 검사를 작성하고 정상 경로 및 기존 fallback을 잠급니다.
2. 이미지 오류의 종료 조건을 바로잡고 RSS 갱신 실패 원인을 보존합니다.
3. 미사용 지도 상태값, 이미지 상수, 옛 로고 주석, 도달 불가 RSS 분기를 삭제합니다.
4. 기존 지도 utility와 RSS 정규화 함수를 재사용하여 중복을 제거합니다.
5. Tailwind 탐지를 현재 앱과 루트 HTML로 제한하고 미연결 설정을 삭제합니다.
6. Node 20 빌드, RSS 검사, 지도 단위 검사, 현재 화면의 브라우저 검사를 실행합니다.
7. 독립 코드 검토와 데스크톱·모바일 화면 비교로 결과를 확인합니다.

## 보존할 동작

- 다크·옐로 디자인, 실제 사진, 연락처·영업시간, 연락 및 길안내 흐름.
- 데스크톱 6개·모바일 3개, 같은 수만큼 더보기, 화면 크기 변경 시 현재 목록 초기화.
- RSS 원문 제목, 요약·날짜 표시, 자동 높이 썸네일과 네이버 원본 비율 URL.
- 정적 피드 → 실시간 프록시, 이전 캐시·이미 표시한 메모리 데이터 유지.
- localStorage quota/privacy 오류가 데이터 표시를 막지 않는 동작.
- 네이버 SDK 미탑재 시 고정 좌표 사용 및 임베드 지도 대체.
- 주소 조회 우선순위, 지도 생성 후 좌표 보정, 기존 앱·웹 대체 타이밍.

## Fallback 분류

| 경로 | 분류 | 처리 |
| --- | --- | --- |
| 원본 이미지 → 기본 사진 | fail-safe 목적, 부정확한 종료 조건 | 절대 URL 비교로 반복 교체 종료, 양쪽 실패 검사 |
| 정적 피드 → 실시간 RSS | 외부 데이터 경계의 fail-safe | 유지, 실패 이유 진단 보존 |
| 최신화 실패 → 저장된 데이터 | fail-safe 목적, 실패 증거 소실 | 데이터 유지와 안내·재시도, 두 실패 원인 보존 |
| 수집 실패 → 검증된 이전 캐시 | 검증된 fail-safe | 기존 RSS 검사와 함께 유지 |
| 오래된 wsrv·네이버 썸네일 URL | 좁은 호환 경계 | 원본 비율 정규화 유지 |
| localStorage 사용 불가 | 선택적 저장소의 fail-safe | 메모리 데이터 표시 유지 |
| 지도 SDK 미탑재 → 임베드·고정 좌표 | 문서화된 fail-safe | 유지, SDK mock 및 미탑재 경로 검사 |

작은 글씨, 영문 라벨, 그림자, 반복 CTA는 디자인 검토 항목으로 남깁니다.
영업시간 정책, 네이티브 앱 실행 판정, HTTP body timeout 범위는 이번 정리에서 변경하지 않습니다.
테스트 파일은 PR에서 제외하고 로컬 검증에만 사용합니다. 병합·배포는 이번 PR 요청에 포함하지 않습니다.
